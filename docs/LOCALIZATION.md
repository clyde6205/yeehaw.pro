# Localization

Status at the commit that introduced it: **10 languages + English ship in the app; all 10 translations are machine translations that no native speaker has reviewed.** They must not be described as native-quality.

## Architecture

| Piece | Where |
|---|---|
| English source of truth | `tools/i18n/en.json` (key → text) |
| Per-language text | `tools/i18n/<code>.json` (same keys) |
| Generated Android resources | `app/src/main/res/values*/strings.xml` — **generated, do not edit by hand** |
| Generator + validator | `python3 tools/i18n/generate.py` |
| Brand names (not translated) | `app/src/main/res/values/app_strings.xml` |
| Runtime language selection | `app/src/main/java/app/yehaw/browser/LocaleHelper.kt` |
| UI | More ▸ Language (native names, plus “System default”) |

`generate.py` fails (exit 1) when: a key is used in code but missing from `en.json`; a key in `en.json` is unused; a language is missing keys or has extra keys; a translation changes the set of format placeholders (`%1$s`, `%2$d`, `%%`). Run it before every commit that touches strings.

Adding a string: put the key in `en.json`, use `getString(R.string.key[, args])` in Kotlin, add the translation to every `<code>.json`, run the generator.
Adding a language: create `<code>.json`, add it to `FOLDERS` in `generate.py` and to `LocaleHelper.SUPPORTED`, run the generator.

Behavior:
* Default is **System default**: Android's normal resource matching, so an unsupported phone language falls back to English.
* A language picked in the app is stored in `SharedPreferences` (`yeehaw_language`) and applied in `attachBaseContext` of both `MainActivity` and the isolated `PrivateBrowserActivity`; the activity is recreated on change. Layout direction follows the locale (RTL for Arabic and Urdu; Hebrew/Persian are RTL with English text until translated).
* Choosing a non-English language shows a notice that it is a machine translation.
* Sizes use `Formatter.formatShortFileSize` (localized units). No string depends on a count-based noun, so no `<plurals>` exist yet; add them when a count-dependent sentence is introduced.
* Search engine names, brand names (YeeHaw, ChatMe, Turbo, WhatsApp…), URLs and HTTP/JS tokens are intentionally not translated.

Known quality risks to give reviewers first: grammatical agreement in the permission sentence (`msg_site_wants_permission`, camera/microphone noun inserted into a sentence — worst in Russian, Arabic, Hindi, Bengali, Urdu); tone/register of security prompts; “Turbo”, “Memory Saver” and other feature names (kept in Latin or lightly translated, a reviewer should decide); length of the privacy-consent text in each language.

## Not yet localized (remaining English)

* The bundled start page HTML (`assets/`) and the public website — separate from the Android UI.
* Server-provided text: update/pause messages from the backend `app-config` (`status.message`, `blockedReason`) are shown as sent by the server.
* Text produced by the system WebView itself (error pages, JS dialogs, permission prompts) follows the WebView/Android language, not this app setting.
* `ShareCore.message` (the text that is shared with the download link) has its own small language table (en, fil, id, hi, bn, vi, es, pt); it does not yet cover zh-CN, ar, ru, ur.

## Tests

`app/src/androidTest/.../LocalizationTest.kt` (runs in the emulator matrix): every shipped language launches the real browser, has the right layout direction, translated labels, ≥48 dp touch targets and a label on every button; Hebrew and Persian are RTL with English fallback; the choice survives activity recreation and a fresh launch; an unknown saved tag falls back to English without a crash.

Not covered automatically (needs a person): visual review of every dialog at small widths and large fonts per language, bidirectional text edge cases (URLs inside Arabic/Urdu sentences), and the language picker dialog itself.


## Coverage audit (255 strings per language)

Generated by `python3 tools/i18n/audit.py` into `docs/TRANSLATION_AUDIT.md`. Every language has all 255 strings. 241-250
differ from English; the rest are brand names (YeeHaw Pro, WhatsApp, Messenger, Telegram, Viber, SMS) or words that are the
normal word in that language ("Offline", "Apps", "OK"). The six non-Latin-script languages have no string lacking their script
apart from those brand names. All are MACHINE TRANSLATION and none has been reviewed by a native speaker.

Still English everywhere (not yet extracted): the bundled start page (`assets/startpage.html`), the product website, update/pause
text supplied by the server, and the ShareCore message table for zh/ar/ru/ur (falls back to English).

Layout: Arabic and Urdu are RTL with translations. Hebrew and Persian are RTL with English text (no translation shipped).
`LocalizationTest` runs every language at 1x and 1.5x font and checks direction, touch targets >= 48dp, labels, and persistence.
